Why a Confluence table breaks when pasted into Excel

Random merged cells, codes that lose their zeros, order numbers in scientific notation, ranges that turn into dates. None of it is random. We pasted a test table into Excel and watched each step.

Short answer. The "random" merged cells come from cells that hold more than one line. Excel turns every line into its own row and then merges the neighbouring cells to keep the table aligned. The other damage comes from Excel guessing types: 007 becomes 7, a 19-digit ID loses everything after the 15th digit, and 1-2 becomes a date. Unmerge and flatten the multi-line cells before copying, or export the table to a file that tells Excel what each cell is.

The question has been sitting on the Atlassian Community for years under titles like "unable to get very large Confluence tables out into Excel, cells will randomly merge". Here is what is going on.

The test

We put a small table on the clipboard exactly the way a browser hands it over when you copy from a Confluence page: as HTML, with one cell spanning two rows, one spanning two columns, and one cell holding two paragraphs. Then we pasted it into a blank sheet in desktop Excel with a plain Ctrl+V.

Then we tried to sort the result by amount. Excel refused: "To do this, all the merged cells need to be the same size." That message is usually where people give up and start fixing rows by hand.

The worst row is not the one that looks broken. The ID that lost four digits looks like a perfectly normal number. Nobody notices until a lookup against the real system finds nothing.

Why it works this way

When you copy from a web page, the clipboard carries HTML. Excel reads that HTML the same way it reads an old web-page workbook, and two of its rules cause all the trouble.

First, a line break inside a cell, whether a <br> or a second paragraph, means "new row" to Excel's HTML reader. To keep the other columns lined up, Excel merges them across the new rows. People have been reporting this in Microsoft's forum since at least 2020, for tables copied from email as well as from the web.

Second, Excel guesses the type of every value. Microsoft documents the conversions it applies when you paste external data: it removes leading zeros, keeps only the first 15 digits of long numbers, reads digits around the letter E as scientific notation, and turns date-like strings into dates. See Set automatic data conversions.

What Confluence itself offers

Confluence Cloud exports whole pages to PDF and Word, and whole spaces to PDF, CSV, HTML or XML. The space CSV is a dump of content for moving between systems, not a spreadsheet of your tables. There is no export for a single table. So for most people the clipboard is the route, and the fixes below are about making the clipboard behave.

Fixes that work, and one that does not

1. Flatten multi-line cells before copying

In the Confluence editor, replace line breaks inside cells with a separator such as "; " and unmerge spanned cells, repeating the value in each cell. Then copy. Tedious, but it removes the cause of the merges completely. On a copy of the page, not the original, if other people rely on its layout.

2. Turn off Excel's automatic conversions

In Excel for Microsoft 365 and Excel 2024: File → Options → Data → Automatic Data Conversion, on a Mac Excel → Preferences → Edit. Untick the options you do not want. This is per computer, so everyone who pastes needs to do it, and older Excel versions do not have the setting at all.

3. Route a multi-line table through Google Sheets

The accepted answer in that Microsoft thread is to paste into Google Sheets first and copy from there into Excel; according to the people who confirmed it, Sheets keeps the lines inside one cell. We have not tested this route ourselves, but for a one-off it is quick to try.

4. Paste into a single cell in edit mode

For one stubborn cell: double-click it, or press F2, and paste. The text stays in that cell. Useless for a whole table, handy for the last two cells that went wrong.

What does not help: formatting the column as Text first

This is the most common advice, and with a normal paste it did nothing in our test. We set the whole sheet to Text, pasted, and still got 7, 1.23E+18 and dates. The pasted HTML brings its own formatting and overrides yours. Format as Text works for typing and for plain-text imports, not for a table pasted from a browser.

The arithmetic

Take a 120-row status table where a third of the rows have a multi-line "Notes" cell. After a plain paste you have roughly 200 rows, about 40 of them blank or half-empty, and a block of merged cells that blocks sorting and filtering. Unmerging, deleting the empty rows and pulling the notes back together is half an hour of careful work, and the IDs that lost digits cannot be repaired at all: you have to copy them again from the source. If the table is exported every month, that is six hours a year spent cleaning the same mess.

If your table is short, has no line breaks inside cells and no codes with leading zeros, none of this applies. Copy, paste, done. Take the free route.

What an export tool has to get right

An export file can tell Excel what each cell is instead of letting it guess: keep line breaks inside the cell, mark codes, long IDs and date-like ranges as text, mark real numbers as numbers so sums work under any regional settings, and repeat merged values so every row has the same columns.

Frequently asked

Why do cells merge randomly when I paste a Confluence table into Excel?

Because some cells contain more than one line or paragraph. Excel splits each line into its own row and merges the other cells in that row to keep things aligned. Look next to any merged block: there is a multi-line cell.

Why did 007 become 7?

Excel treats it as a number and drops the zeros. Turn off "Remove leading zeros and convert to number" under Automatic Data Conversion, or make sure the value arrives marked as text.

Why did a long order number turn into 1.23E+18?

Excel stores at most 15 significant digits. A longer number is rounded, and the digits after the 15th become zeros. Widening the column will not bring them back.

Does Paste Special → Text avoid all this?

It avoids the formatting and the merged cells, which is why our guide to getting a table into Excel recommends it for simple tables. The type guessing still applies to plain text, so codes and long IDs can still be converted.

Does Google Sheets have the same problems?

Users in Microsoft's forum report that Sheets keeps multi-line cells in one cell, which is why it works as a stepping stone. Sheets also guesses types for numbers and dates, so check codes and IDs there too.
