How to import Word documents into Confluence Cloud

The import is built in and free. This is where it lives, what survives the trip, what quietly breaks, and the point at which a document migration stops being something you finish in an afternoon.

Short answer. Create a page, then next to the Share button open More actions → Templates and import → Import, choose Word document (.docx), and pick your file. No app required. One file becomes one page: headings, tables and images come across, drawn shapes do not.

The built-in import, step by step

  1. Select Create in the top navigation to open a blank page.
  2. Next to Share, open More actions, then Templates and import, then the Import tab.
  3. Choose Word document (.docx) and select the file.
  4. Read the result before publishing, and move the page to where it belongs in the tree.

Do this once with a real document from your archive before planning anything bigger. Five minutes here will tell you more about your migration than any estimate.

What survives, and what does not

In the Word fileAfter import
Heading styles (Heading 1, 2, 3)Become Confluence headings, and the page gets a usable outline.
Text made large and bold by handStays large and bold text. Not a heading, so it is invisible to the table of contents.
Simple rectangular tablesCome across intact.
Merged cells and nested tablesUsually survive, but check them: complex layouts are where import problems hide.
ImagesAttached to the page and shown in place.
Shapes and drawing objectsReplaced with placeholders. This is documented behaviour, not a bug.
Text boxes, headers and footersDo not come across in any useful form.
Tracked changes and commentsDo not come across. Accept or reject them in Word first.

Prepare the document, not the import

Almost every disappointing import is a document problem rather than a Confluence problem. Three habits fix most of it.

Use real heading styles. If your authors made headings by increasing the font size, Confluence has no way to know what is a heading. Applying Heading 1 and Heading 2 in Word before import is ten minutes that saves an hour of cleanup.

Flatten the drawings. Anything drawn with Word shapes — a process diagram, a boxed callout, an org chart — will arrive as a placeholder. Screenshot it, or export it as an image, and put the image in the document instead.

Clean the file. Accept tracked changes, delete comments, and remove the cover page if it exists only for the printed version. Confluence pages do not need cover pages, and everyone who imports one deletes it afterwards.

Where the built-in import stops

The import is genuinely good for what it is. It runs into three walls, and all three are the same wall: it was built for a document, not for an archive.

One file, one pageA 90-page regulation becomes a 90-page Confluence page. Nobody reads that, and nobody can link to a section of it. Splitting it into a tree by heading level is manual work.
One file at a timeFine for five documents. For a hundred and fifty, it is a week of somebody clicking through the same four menus, and the week never gets scheduled.
No structure across documentsEach import lands where you happen to be. Turning a folder of files into a coherent space with parents and children is a separate job, done by hand.

This is why so many Confluence migrations stall halfway. The tooling handles the document in front of you and has nothing to say about the shared drive behind it.

When the archive is the problem

The honest test is arithmetic. Count your documents and multiply by fifteen minutes, which is a realistic figure once you include fixing headings and placing the page. Twenty documents is a morning. A hundred and fifty is four working days that nobody has, which is exactly why those files are still sitting on the shared drive two years after the decision to move.

Disclosure: I build Word Import for Confluence, which exists for that second case: drop a batch of files, get a page tree, with documents split by heading level rather than dumped as one long page. It reads the files inside your browser, so nothing is uploaded to a third party — which matters when the documents are regulations, contracts or HR policies. It is free for teams up to ten people.

Frequently asked

Does the import work on mobile?

Do it from a desktop browser. The import lives in the page creation menu, which is awkward on a phone, and you will want to check the result on a large screen anyway.

What about .doc files from the nineties?

Open them in Word and save as .docx first. The old binary format is not accepted, and converting it also gives you a chance to fix the heading styles.

Can I import a PDF the same way?

No. PDF is a layout format with no reliable structure inside, so any conversion is guesswork. If the PDF was generated from a Word file, find the original and import that instead.

We are moving from SharePoint. Same story?

Mostly. The files are usually .docx underneath, so the same rules apply — with the extra step of deciding what not to bring. A migration is the one moment when deleting outdated documents is easy, and it is worth pairing this with a look at what nobody maintains any more.
