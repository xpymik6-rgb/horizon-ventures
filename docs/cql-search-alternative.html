Looking for a CQL Search alternative

CQL Search puts the results of a Confluence query on a page. It runs on a platform Atlassian stops supporting on 31 January 2027. Here is what replaces it, starting with what Confluence already does for free.

Short answer. CQL Search is a Connect app with around 980 installations, and its last release was on 11 July 2024. Atlassian ends support for Connect on 31 January 2027 and warns that breakages will grow after that date. For a live list on a page, the native filter by label macro covers most simple queries, except anything with a relative date such as "not updated for 180 days". For those, or for a query you want to keep writing in CQL, a Forge app is the replacement: Canned Search, Search Results Macro+ or Smart Search.

What is happening to CQL Search

Connect is the older way Atlassian apps were built: the app runs on its vendor's servers and talks to your site over the network. Forge is the newer one, where the app runs inside Atlassian's own infrastructure. Since March 2026 Connect apps can no longer ship updates, and Atlassian moved the end of support from December 2026 to 31 January 2027.

Nothing announces itself on that date. Connect apps degrade: a macro fails on some pages, then on more of them, then shows an error box where the list used to be. The pages that depend on a saved query are usually dashboards and indexes that people open every day, so this is noticed quickly, just not in advance.

If the vendor ships a Forge version, the problem goes away. The way to check is on the app's Marketplace page: a release dated 2026 and the "Runs on Atlassian" badge mean it has moved. As of October 2026 CQL Search shows neither.

What Confluence does natively

Filter by label: the closest native replacement

The name undersells it. Labels are only the first filter; you can add space, title, text, creator, contributor, type, child pages and dates, and the macro assembles the CQL behind the form. The result is a live list on the page, which is most of what CQL Search was used for. Multiple values in one filter mean OR, the same filter added twice means AND, and a minus sign excludes.

Where it stops: dates are fixed dates. "Last modified before 1 March" works; "not modified for 180 days" does not exist, and a pinned date makes the list wrong a week later. Queries that lean on labels also inherit a habit problem, because the pages people forget to maintain are the pages nobody labelled.

The search results macro

It runs a CQL query and prints the hits, which is exactly CQL Search's job. It belongs to the legacy editor, whose deprecation started in January 2026, so it is a place to keep an old page alive, not to build anything new.

Live Search, advanced search and automation

The Live Search macro is a search box: it shows nothing until someone types, so it does not replace a saved list. Advanced search filters by space, contributor, label and last modified date, but its results stay in the search screen. A scheduled automation rule accepts CQL, including relative periods like lastModified < now("-180d"), and can email page owners; it notifies, it does not put a list on a page.

How to move, and how long it takes

  • Find every page that uses it. Open one page with the macro, note the macro name in the editor, then run macro = "that-name" as a CQL query through the REST API. That list is the whole job.
  • Copy each query out while it still renders. The query lives inside the macro. If the macro stops loading, reading the parameters back gets harder, so collect them now into one page or spreadsheet.
  • Sort by what the query needs. Plain filters by space, label or author go to filter by label for free. Anything with a relative date or a complex condition goes to an app.

The arithmetic is gentle: a site with 30 pages using the macro is about 30 queries to copy and rebuild, five minutes each, so two or three hours in total. The cost is not the hours; it is doing it before the dashboards break rather than after.

Where Smart Search fits

Disclosure: I build Smart Search. It is a Forge macro that keeps a live list of pages on a page, across spaces, from conditions picked in dropdowns: space, labels, words in the text, author, and relative dates such as "not updated for 180 days". It shows in plain English what the list will contain before you save, and the CQL it generated is one click away; if you prefer to write the query yourself, you can. It does not do bulk moves or reports, which is where Canned Search is the better fit. It is free for up to 10 users. Marketplace listing.

If filter by label covers your queries, use that. It is free, native, and it will not be retired.

Frequently asked

Will CQL Search stop working on 31 January 2027?

Not necessarily that day. 31 January 2027 is when Atlassian ends Connect support; after it, the app gets no fixes when something on the Confluence side changes, and failures accumulate. Plan to have replaced it by then rather than waiting for the first broken page.

Can I keep my queries exactly as they are?

The CQL itself is standard Confluence Query Language, so a query written for CQL Search runs anywhere CQL is accepted: the REST API, automation rules, and apps that take raw CQL. What changes is the macro that displays the result.

Is there any official migration tool?

No. Atlassian's migration tooling moves content between sites; it does not convert one vendor's macro into another's. Each page is rebuilt by hand or by script.

What if the vendor releases a Forge version after all?

Then keep it. Check the listing for a 2026 release and the "Runs on Atlassian" badge before you start moving pages. See also our note on what the Connect end of life means for admins.
